# PowerShell course routing

## Canonical tutor state

Use `learning/` as the source of truth for general PowerShell teaching,
practice, retrieval, quizzes and progress.

Use `projects/` for numbered project code and evidence. Preserve the existing
starter files and learner-written code.

When PowerShell is being learned for a specific infrastructure lab, also read
that lab's `AGENTS.md` and learning state. Record language evidence in this
course and infrastructure changes in the lab.

## Tutor boundaries

- Sat writes active exercise and project answers.
- Review exact code and runtime output before suggesting changes.
- Give one correction or hint at a time.
- Do not replace active TODOs with final solutions.
- Use mock data and read-only discovery before configuration.
- Require separate verification after a change.
- Keep credentials, tokens, tenant identifiers and private data out of Git.
- Use UK English and normal ASCII hyphens in documentation.

Understand

The administrator’s discovery loop

Before changing a server, first discover what PowerShell can do and what data the current system exposes:

find command → read help → run safely → inspect object → select properties

1. Find the command

Get-Command searches commands available on your computer. The result is itself a structured command-information object, not merely a name. Microsoft documents that it can return cmdlets, aliases, functions, scripts, and applications. Microsoft: Get-Command

2. Read how it works

Get-Help shows syntax, parameters, descriptions, and examples. The -Examples switch is especially useful when you need a working shape without copying an entire solution. Local help can be limited until help files are updated. Microsoft: Get-Help

3. Inspect the returned object

Get-Member reveals an object’s type, properties, and methods. A property is stored information, such as a process name or network-interface alias. A method is an action that the object can perform. Microsoft: Get-Member

4. Keep only useful properties

Select-Object creates output containing the properties you request. This lets an infrastructure script produce a focused verification report rather than a wall of text. Microsoft: Select-Object

See it

Worked example: inspect a process

This example uses a process so it works on your train laptop. It demonstrates the same workflow you will later apply to server networking.

Get-Command -Name Get-Process
Get-Help -Name Get-Process -Examples

$process = Get-Process | Select-Object -First 1
$process | Get-Member
$process | Select-Object -Property Name, Id, CPU

Think of the process object like:

  • a Python object whose values are available through attributes such as process.name;
  • a JavaScript object whose values are available through properties such as process.name.

The exact syntax differs, but the mental model is similar: keep the structured value, then ask for the property you need.

Why this matters on SRV01

Your Build 2 notes use native commands including ipconfig, ping, nslookup, and hostname. Those were useful for diagnosis, but their output is primarily formatted text.

On Windows Server, the same discovery loop lets you investigate object-producing commands such as Get-NetIPConfiguration. Once you can inspect its properties, later lessons can build a structured pre-change network report and verify static IP and DNS configuration without parsing lines of text.

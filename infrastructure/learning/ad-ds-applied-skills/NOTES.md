# Teaching Notes

## Preferences

- Use short, step-by-step explanations and one active task at a time.
- Sat attempts commands and configuration; Codex reviews before revealing a
  complete procedure.
- Explain every new command, value, object, permission, risk, expected result,
  and verification method.
- Compare PowerShell with Python or JavaScript when it shortens the learning
  curve.
- Use retrieval, repetition, and fresh variations instead of treating a single
  successful run as mastery.
- Track every first-attempt quiz miss and carry recurring weak points into a
  final remediation quiz. Give the correction briefly, but defer fresh retry
  variations until the end so the main module keeps moving.
- Link to the exact official Microsoft page used for each new concept.
- Keep the Microsoft Learn page and the local companion open side by side.
- Tell Sat exactly when a screenshot is useful and what it must prove.
- Keep canonical progress in Markdown so another computer or Codex task can
  continue from the repository.

## Prior knowledge

- Has built and documented a Windows Server 2025 domain, AD objects, a Windows
  11 domain client, Group Policy, and departmental file services.
- Has basic PowerShell experience with variables, arrays, loops, custom
  objects, pipelines, filtering, functions, and AD administration scripts.
- Benefits from rechecking syntax and behaviour through short drills.
- Has not yet demonstrated all APL-1008 study-guide operations independently.

## Constraints

- Run state-changing commands only in an authorised disposable lab.
- Establish snapshots and rollback boundaries before topology, functional
  level, domain-controller, Recycle Bin, authentication, or policy changes.
- Do not copy the published credentials from Microsoft guided-lab pages into
  this repository or reuse them elsewhere.
- A Microsoft Learn completion marker is not independent performance evidence.
- The final local mock is preparation only and is not Microsoft's assessment.

Create and manage AD objects

Manage identities safely, repeatably, and with evidence that proves the intended lifecycle state.

Outcome

You can manage users, groups, OUs, bulk changes, gMSAs, and deleted objects.

Official module: 2 of 5

Retrieve first

Object model

Compact model

An OU provides administrative and Group Policy scope. Attributes describe an object. Security groups normally carry access. Bulk automation should validate first, preview when possible, produce a result for every row, and be safe to rerun.

$password = Read-Host "Enter an initial password" -AsSecureString
New-ADUser -Name "Ava Patel" -SamAccountName "ava.patel" `
    -Path "OU=Users,OU=Lab,DC=example,DC=test" `
    -AccountPassword $password -Enabled $true `
    -ChangePasswordAtLogon $true

Worked reasoning

Secure lifecycle evidence

A successful cmdlet is only the change attempt. Query the resulting account, OU, membership, enabled state, or resultant policy independently. Never record the supplied password.

Learner task

Complete module 2 and its assessment

Then create one disposable user and group. Build a three-row CSV with one valid row, one duplicate, and one invalid row. Produce a validation report before any bulk change.

Hint 1

Separate validation from mutation.

Hint 2

Your report needs a result for every row: ready, duplicate, or invalid.

Module 2 check

1. Which object normally grants file access?

A. OU
B. Security group
C. City attribute

2. What PowerShell value type should carry a new AD password?

3. What domain prerequisite supports gMSA password generation?

4. What should a rerun-safe bulk script do with an existing account?

A. Create it again
B. Detect and report it
C. Delete it

5. What proves Recycle Bin recovery?

A. The restore command returned
B. The object is back in the correct location with key attributes
C. The deleted-object list was opened

Answer explanations
  1. Security groups normally carry access.
  2. AD password parameters accept SecureString values.
  3. A usable KDS root key is required for gMSA password generation.
  4. Detect and report duplicates so reruns are safe.
  5. Verify restored location and attributes.

Security reasoning

Compact model

Least privilege means the smallest task, group, scope, and duration that solve the requirement. Positive tests prove needed access. Negative tests prove excluded access. Authentication restrictions need audit, staged rollout, monitoring, and rollback.

auditpol /get /category:*
gpresult /scope computer /r

Worked reasoning

Audit before deny

Blocking NTLM without a dependency baseline can break old applications and administration paths. First audit usage, find the dependent system, remediate it, stage the restriction in the isolated lab, test expected failure, and keep a recovery path.

Learner task

Complete module 4 and its assessment

Design a help-desk delegation that can reset passwords only inside one test OU. Write one positive and two negative tests before applying it. Then implement and record the results.

Hint 1

Delegate to a group, not directly to an individual.

Hint 2

Negative tests should cover another action and another OU.

Module 4 check

1. Which is the strongest delegation evidence?

A. Intended action succeeds
B. Intended action succeeds and excluded actions fail
C. The wizard closes

2. What should happen before NTLM is denied?

3. Which normally takes priority when an account has both an allow and matching deny user right?

4. Which group adds strong authentication restrictions that can break legacy workflows?

5. What does a generated audit event prove by itself?

A. The policy is deployed correctly everywhere
B. That the audited activity was logged on that system
C. That NTLM can be blocked safely

Answer explanations
  1. Positive and negative tests establish the boundary.
  2. Audit dependencies before deny.
  3. Deny rights normally override allow rights.
  4. Protected Users adds authentication restrictions.
  5. The event proves that event was logged, not universal deployment or compatibility.

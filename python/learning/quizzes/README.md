# Python Quiz System

Quizzes are active coding checks, not answer sheets. The tutor creates the quiz
when a project reaches its exit gate so its questions can reflect the code Sat
actually wrote and the help he used.

## Project exit quiz

Every project ends with six no-notes parts:

1. Explain the central mental model.
2. Predict output or program state.
3. Diagnose a bug, traceback or failing test.
4. Write a short Python fragment from a requirement.
5. Justify a design, reliability or safety decision.
6. Transfer the skill to different data or an infrastructure scenario.

## Review rules

- Show one question at a time.
- Do not store or reveal an answer key before the attempt.
- Record help as None, Hint, Partial or Full.
- A correct guess without explanation is not secure evidence.
- A missed item creates a changed mini-lab in `../practice/`.
- Ask a new version of the question after the mini-lab.
- The project closes only when every gap is repaired and the code runs.

## Phase gates

After Projects 04, 08, 12, 16, 20 and 24, use a cumulative quiz plus a small
build from requirements. The build must combine skills from the whole phase and
at least one earlier phase where available.

Quiz files use names such as `project-01-exit-quiz.md` and
`phase-a-coding-gate.md`. They contain questions and attempt status, not a visible
solution bank.

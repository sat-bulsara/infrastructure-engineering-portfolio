# Python Repetition System

The course uses a spiral rather than teaching each concept once.

| Pass | Timing | Support | Evidence |
| --- | --- | --- | --- |
| Learn | Current project | Guided or Partial | First correct use and explanation |
| Immediate variation | Same or next project | Hint | Changed data or rule |
| Interleaved recall | Two to four projects later | Hint or None | Correct selection without a reminder |
| Phase gate | Every fourth project | None before attempt | Cumulative quiz and mini-build |
| Delayed transfer | Later phase | None | Skill reused inside a different tool |
| Capstone | Project 24 | None | Independent design, debugging and explanation |

For every project after Project 02, the brief names at least two earlier skills
to reuse. One must use less support than before. The tutor records skills rather
than repetitions completed, because repeating the same copied code does not
improve fluency.

If recall fails, return to a small changed mini-lab, then recheck with new data.
Do not restart the entire project unless the underlying mental model is missing.

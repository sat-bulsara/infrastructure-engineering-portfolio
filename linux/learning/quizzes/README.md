# Linux Quiz System

Quizzes are active operations and coding checks, not command memorisation. The
tutor creates the quiz when a project reaches its exit gate so its questions can
reflect the actual lab, script and help used.

## Project exit quiz

Every project ends with six no-notes parts:

1. Explain the central Linux or shell mental model.
2. Predict a command, pipeline or script result.
3. Diagnose a command failure or Bash bug.
4. Write a short Bash fragment from a requirement.
5. Justify a privilege, security or rollback decision.
6. Transfer the skill to a different host, path, user, service or dataset.

## Review rules

- Show one question at a time.
- Do not store or reveal an answer key before the attempt.
- Record help as None, Hint, Partial or Full.
- A successful copied command is not secure evidence.
- A missed item creates a changed mini-lab in `../practice/`.
- Ask a new version of the question after the mini-lab.
- The project closes only when every gap is repaired and the script is verified.

## Phase gates

After Projects 04, 08, 12, 16, 20 and 24, use a cumulative quiz plus a small
script built from requirements. The script must combine skills from the whole
phase and at least one earlier phase where available.

Quiz files use names such as `project-01-exit-quiz.md` and
`phase-a-shell-gate.md`. They contain questions and attempt status, not a visible
solution bank.

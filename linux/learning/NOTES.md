# Teaching Notes

## Preferences

- Use short, step-by-step explanations and one active command or question.
- Explain the target and likely effect before asking Sat to run a command.
- Compare with Windows, PowerShell and macOS when useful.
- Prefer real terminal output from a disposable Linux lab.
- Use repetition, changed scenarios and controlled break/fix to build fluency.
- Provide one focused official documentation or local man-page reference.
- Review the exact output before giving the next command.
- Make every project include Bash or later justified Python code, with repeated
  coding, practical quizzes and cumulative phase gates.
- Present quiz questions one at a time and repair gaps through changed scripts.
- Use UK English and do not use em dashes.

## Prior knowledge

- Sat has used simple terminal and Git commands on macOS.
- PowerShell learning has provided some familiarity with variables, pipelines,
  loops, objects and functions.
- No Linux-specific administration skill has yet been demonstrated in this course.

## Constraints

- System-changing work must use a disposable, authorised Linux environment.
- The Mac terminal is useful for comparisons but is not evidence of Linux system
  administration where behaviour differs.
- Some learning happens while travelling, so reading and low-risk drills should
  remain portable.
- Do not infer mastery from pasted commands or an empty success response.
- The Linux tutor owns operating-system administration. The Python tutor owns
  Python language and software-engineering progression.

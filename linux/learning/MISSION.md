# Linux Learning Mission

## Topic

Linux administration, troubleshooting, security and automation.

## Why this matters

Build practical Linux confidence for infrastructure and cloud engineering. Sat
should understand what the system is doing, make controlled changes, investigate
evidence and recover safely rather than memorising commands without context.

## Real-world outcome

Operate, secure, troubleshoot and automate authorised Linux systems through
progressively independent projects.

## Constraints

- There is no artificial deadline. Operational judgement matters more than speed.
- Keep one concept and one small terminal action active at a time.
- Linux-specific administration has not yet been demonstrated in this course.
- Use a disposable Ubuntu VM or equivalent authorised lab for system changes.
- Some study may happen on a laptop while travelling, so reading and safe drills
  should work offline where possible.
- Confirm the target before commands and avoid production systems.
- Use least privilege, snapshots or rollback and public-safe evidence.
- Use UK English, direct wording and no em dashes.

## Completion evidence

- [ ] Complete Projects 01-24 progressively with verified scripts, evidence and quizzes.
- [ ] Navigate and manipulate files safely without exact command instructions.
- [ ] Explain users, groups, permissions, processes, services, packages, storage,
      networking and logs in Sat's own words.
- [ ] Diagnose controlled failures using commands, logs and a clear hypothesis.
- [ ] Secure remote access and a small service using least privilege.
- [ ] Write and troubleshoot a reusable Bash operations tool.
- [ ] Recover a broken lab service and explain the root cause and prevention.
- [ ] Use Python appropriately in a later Linux operations task without confusing
      language learning with operating-system administration.
- [ ] Repair every missed project and phase-gate quiz item through changed commands
      and code, not by memorising an answer key.

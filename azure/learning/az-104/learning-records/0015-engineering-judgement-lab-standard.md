# Engineering judgement lab standard

- Date: 2026-09-01
- Status: Active
- Context: A supplied transcript argued that service recognition and certification
  alone do not demonstrate the system design, cost discipline and security
  reasoning expected from a cloud engineer.
- Evidence: No new Azure capability was assessed. The advice was compared with
  the existing project-first curriculum and adapted only where it strengthened
  observable engineering evidence.
- Learning: Substantial projects and independent mini-labs now start from a
  business problem and constraints. They require a defence of the selected and
  rejected design, verified cost reasoning, a security pre-mortem and an
  evidence-based monthly statement of what new problem can be solved.
- Boundary: External claims and promotional statistics are not treated as
  authoritative Azure evidence. Current Azure behaviour, pricing and security
  guidance still require official Microsoft sources.
- Revisit when: Completing each independent project review and at the first
  monthly capability comparison.
